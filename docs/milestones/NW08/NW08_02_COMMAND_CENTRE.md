# NW08.2 — Admin Command Centre

## 1. What changed

**`src/lib/admin/analytics.ts`** (pure, unit-tested helper module) gained four new, dependency-free, pure functions: `tallyByKey()` (generic in-memory string-key tally), `bucketRevenueByMonth()` (trailing-month, per-currency, zero-filled revenue trend), `rankOperationalAlerts()` (filters zero-count candidates, sorts critical→warning→info then by count), plus the `RevenueTrendPoint`/`CurrencyRevenueTrend`/`OperationalAlertInput`/`AlertSeverity` types. 11 new tests added to `analytics.test.ts` (19 total in that file now, all passing).

**`src/lib/supabase/admin/dashboard.ts`**'s `getAdminDashboardSummary()` (still gated by the same single `dashboard:read` permission as before — no new permission requirement introduced) gained: `recordedRevenueByCurrency` (replacing the old, incorrect single-currency field — see §2), `revenueTrend` (trailing 6 months, per currency), `pendingRefundsCount` (non-terminal `refunds.status`), `serviceDeliveryBreakdown` (reusing `student_outcomes.outcome_status`, the same column Milestone 9's `getOutcomeStatusDistribution()` reads), and `operationalAlerts` (5 real bounded-count checks: overdue leads follow-up, overdue application actions, overdue invoices, refunds awaiting review, refunds awaiting gateway confirmation). Every new query is a single `count: "exact", head: true` or a narrow column-only select — none loads a full table.

**`src/components/admin/CommandCentreWidgets.tsx`** (new) — four presentational-only components (`OperationalAlertsCard`, `RevenueTrendChart`, `ServiceDeliveryDonut`, `SectionCard`). No chart dependency was added (confirmed none exists in `package.json`); the revenue trend is plain inline-SVG-free CSS bars, the donut is a CSS `conic-gradient` ring with a text legend — both standard, dependency-free, accessible (each chart carries `role="img"` + a text `aria-label`, and the legend/bars are also present as real DOM text, not canvas pixels).

**`src/app/admin/page.tsx`** — redesigned: "Admin Studio · Command Centre" branding (matching the mockup), 9 KPI tiles (the original 8 plus "Pending refund cases"; the revenue tile now shows one amount per currency rather than a single, possibly-wrong figure), a new "Operational alerts" + "Service delivery breakdown" two-column section, and a new "Revenue trend" section — all above the pre-existing "Applications needing your attention" / lead funnel / counsellor workload / recent activity sections, which are unchanged.

**`src/components/admin/AdminShell.tsx`** — `ADMIN_NAV`'s 21 items now each carry a `group` field and render under 10 grouped headers (Command Centre, Students & CRM, Applications, Counsellors & Team, Commercial, Finance, Operations, Catalogue, Reports & Analytics, Settings) in the sidebar, matching the brief's suggested IA (extended with "Operations"/"Catalogue" so the university/course/data-quality items — not pictured in the mockup — are not dropped, per the brief's own explicit "never remove an existing capability just because the mockup omits it" instruction). **Every href and every `permission` gate is byte-identical to before this change** — this is a presentation-only regrouping, confirmed by diff. The sidebar badge text changed from "Admin" to "Admin Studio".

## 2. A real pre-existing accuracy bug found and fixed

`getAdminDashboardSummary()`'s old `recordedRevenueMinorUnits`/`recordedRevenueCurrency` fields summed **every** paid payment's `amountMinorUnits` regardless of its own `currency` column, then labeled the total with whatever currency happened to be on the *first* row returned. On a single-currency deployment this is invisible; on any deployment with more than one active payment currency, it would silently mix currencies into one number under one, arbitrary, currency label — exactly the mistake the NW08 brief's §16 rules forbid ("never sum revenue across currencies"). `src/lib/supabase/admin/analytics.ts`'s `getAnalyticsSummary()` already did this correctly (group-by-currency-first, via the same `sumRecordedRevenue()` helper). This milestone fixes `dashboard.ts` to the identical, correct pattern — `recordedRevenueByCurrency: {currency, amountMinorUnits}[]` — and updates the one UI call site (`admin/page.tsx`) accordingly. Both call sites were confirmed via `grep` before the change; no other file referenced the old field names.
